# PAGE N2 — Entry / resume
KIND: checklist
TAGS: research, normal
TRIGGERS: new question; resume; last time; where were we; this paper; start research
OBJECTIVE: Enter or resume a question from originals: the ledger is live, the context is retrieved, user files are registered, domain cards are chosen, and the map is sketched.

ENTRY — object: the K pushed by N1 step 3 on the first message of a question, or when the message resumes earlier work.

◆ Originals, not summaries.

1. **Context sweep (always on entry).** Push one `retrieve <item>` K @RF for
   each of the following. They are queued ahead of the dispatch that exit a
   pushes, so they run first, after this card's `research_done`:
   - the question's key objects and symbols;
   - any earlier work the message names or presupposes.

   RF searches the past chats in scope, reads the project's memory folder for
   pointers, and asks for out-of-scope chats. Anything known only from a
   summary, a snippet, or memory is `[unverified]` or `pointer:`.
2. **Is there a ledger?** Run `research_ledgers(action="list")`.
   - If it exists: run N1 step 1 (`research_begin`).
   - If there is none: run `research_ledgers(action="init", ledger,
     question="<question in the user's words>")`.
   - If it lives elsewhere as an export (another machine, the CLI fallback):
     run `research_ledgers(action="import", data=…)`.
   - If it is lost but was printed earlier: rebuild it with `research_add`,
     copying the printed rows verbatim, with evidence
     `restored: <chat, message>`. Never rebuild from memory.
   - If several sessions printed the same row with different states: the
     **latest** session's state is restored, and the conflict is recorded as a
     `P` row. If it touches a mandatory `C`, ask the user once.
3. Register each file the user provided as a `source` document (card N4).
4. Select the domain cards by the question's **objects**:
   - DOM-FND: foundations;
   - DOM-GA: geometry, algebra, representations;
   - DOM-AV: analysis, variational problems, PDE;
   - DOM-PH: physics;
   - DOM-ML: learning systems;
   - DOM-SI: signal and inverse problems.

   Read only the cards you select, and combine cards only when the question
   genuinely crosses fields. Run each card's ENTRY **from the user's givens
   only**: whatever the user did not give stays a symbol or an `open` row.
5. Put the question and its coarse sub-questions into the map with
   `research_set(id="M", field="content", value=<the whole map>)`, following
   card QM.
6. Go to **N3**.

**EXITS** (each exit returns objects; `<caller>` = the page of the K that routed here)

- **a**: ledger live, question in M, domain cards chosen → push `dispatch U#` @N3 **and**, per chosen domain card, `apply its checks to <objects>` to that card (@DOM-FND, @DOM-GA, @DOM-AV, @DOM-PH, @DOM-ML or @DOM-SI)
- **b**: originals unreachable → push `context loss on <items>` @X8
- **c**: session conflict touches a mandatory C → push `ask the user on P#` @USER

# PAGE REF-DOM — Domain cards
KIND: reference
TAGS: research, reference
TRIGGERS: domain card; IDENTIFY; which field
OBJECTIVE: How domain cards are chosen and what their parts mean.

Consulted from a card step; return to that step. Not a procedure: it consumes no K.

Domain cards add the checks of one field on top of the stage cards. Pick them
in N2 step 4 by the **objects in the user's question**, not by topic words.
Each selected card becomes a plan object pushed to its card (DOM-FND, DOM-GA,
DOM-AV, DOM-PH, DOM-ML, DOM-SI).
Read only the cards you select. Combine two only when the question genuinely
crosses the two fields.

Every domain card has the same shape:

- **EDGES**: the chain of objects this field's work follows.
- **IDENTIFY**: what to identify **from what the user gave**. An item the user did
  not give stays an unspecified symbol, or an `open` row. **Never fill it with a
  default on the main line** (card REF-ORIGIN: that would be a model-origin item).
  A default may still be **explored**: register it as a model premise and
  compare configurations with and without it (EX).
- **CHECKS**: what to run or verify in this field. Use only the checks relevant
  to the task.
- **DO NOT**: the confusions typical of this field.

# PAGE N4 — Documents: sources, deliverables, working files
KIND: checklist
TAGS: research, normal
TRIGGERS: write up; document; markdown; summary document; update the doc; report; user file; 정리; 문서
OBJECTIVE: Keep the user's originals untouched, the user's documents readable and current, and the model's working files out of the reader's way; change a document only through a committed change list.

ENTRY — object: a K @N4 on a document (D#) and the rows it projects.

◆ List the changes first, commit them, then rewrite whole sections. Never
append a correction to a document.

Register every document once with `research_doc(action="register")`, as one of
three roles:

| role | what it is | rule |
|---|---|---|
| source | a file the user provided | read-only; registered with its text; `check` detects any change; edits go to a working copy |
| deliverable | written for the user to read | readable prose; plan → rewrite → sync |
| working | the model's own (exports, scripts, scratch derivations) | never handed over as the deliverable; no reader rules |

**Reader rules for a deliverable.**
- Write for a reader. Use prose in the user's language and LaTeX for
  mathematics. Organize by concept, merging what belongs together; never by
  turn order.
- Follow each `##` heading, on the next line, with a hidden marker
  `<!-- sec:s3 basis: E2 A4 H1 -->`. Ledger ids appear only there.
- The visible text carries no ledger artefacts: no ids in brackets, basis
  tags, tokens, plan objects, card references, or status codes.
- Say status in words:
  - computed → "checked by symbolic computation" (기호 계산으로 확인);
  - measured → "measured numerically over <range>" (수치로 확인);
  - sourced → "from <source>" (출처 확인);
  - followed → "reproduced step by step" (단계 재현);
  - unverified → "not yet verified" (미검증);
  - an exploration verdict → "under the alternative premise …"
    (다른 가정 … 아래에서는).
- Give open problems a section of their own. History stays in the ledger, not
  in the body.

1. Read the current text of the document and pass it as `text`.
2. **Plan.** Call `research_doc(action="plan", doc=D#, text)`. It returns a
   draft change list with:
   - the affected sections;
   - sections citing replaced or stale rows;
   - rows not yet in the document;
   - merge candidates;
   - unplanned edits since the last sync.
3. **Commit.** Decide one op per item and commit it with
   `research_doc(action="plan", doc, text, items=[…], token)`. The ops are:
   - rewrite;
   - merge (into);
   - add (rows), one item per new section, listing every row that section
     brings in;
   - retire;
   - keep (why);
   - omit (rows, why).

   The device refuses an incomplete list.
4. **Rewrite** each planned section whole, from the current ledger. State the
   current result; never keep the old wording with a correction after it.
   Merge sections into one passage. Leave every unplanned section
   byte-identical.
5. **Sync.** Call `research_doc(action="sync", doc, text=<new text>, token)`.
   The device refuses each of the following:
   - unplanned edits;
   - planned sections left unchanged;
   - citations of replaced or stale rows;
   - reader-lint failures.
6. **Source documents.** Call `research_doc(action="check", doc, text)` before
   relying on one. If it has changed, report the change, restore the original,
   and move the edit into a working copy.

**EXITS**

- **a**: document synced → push `await reaction to the document` @USER
- **b**: plan refused as incomplete → push `complete the change list for D#` @N4
- **c**: sync refused → push `fix the listed sections of D#` @N4
- **d**: a source document changed → push `report the edit to the user` @USER

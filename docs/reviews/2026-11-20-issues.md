# RefHandbook code review — issue list before patches

Baseline: `dev` f1b8794; complete tracked-path inventory: `2026-11-20-inventory.md` (411 files).
Review method: enumerate all tracked files; map the MCP kernel, agents and sandbox, portal services, web frame and pages, WordGenerator, deployment, and test suites; search executable sources for execution and archive boundaries, request/auth handling, browser storage, UI navigation and async writes; read callers and nearby tests for each finding. This is a source audit, not proof that every line or runtime path is correct.

## Confirmed issues and patch contracts

| ID | Area | Evidence and reproduction | Patch boundary | Verification |
| --- | --- | --- | --- | --- |
| S1 | Security | `src/refhandbook/agents/recipes/fetch.py:84` evaluates its `--json` argument as Python; `recipes/node.sh:4` passes the one in-tree expression. The helper runs inside a layer build. | Replace expression execution with a fixed latest-LTS selector and literal object-key selection; update its caller. | Valid and malicious selector tests. |
| S2 | Security | `fetch.py:61-75` strips archive path components and extracts members. A crafted `pkg/bin/escape -> ../../../outside` symbolic link was accepted by the baseline in the sandbox. | Check member and link destinations after stripping; retain valid in-tree links. | Hostile and valid archive tests. |
| S3 | Privacy and function | `apps/WordGenerator/src/lib/storage.ts:23-80` uses the same browser keys for every account and automatically uploads local data on a new account's 404. Alice's cached draft can appear in Bob's account and be uploaded there on a shared browser. Server `src/portal/apps.py` scopes its own data correctly; the browser cache defeats that boundary. | Scope cache by UID; do not silently migrate unowned legacy keys into a different account. Keep browser-only storage and a recoverable explicit migration path for existing data. | Two-user shared-browser and legacy migration tests. |
| F1 | Function | `storage.ts:86-116` starts independent PUTs for consecutive saves of the same key. A slow first PUT can finish after the later PUT and leave the server older than the browser. | Serialize writes per key (including debounced writes) without blocking unrelated keys. | Deferred-response test that reverses network completion order. |
| U1 | User experience | `web/src/lib/markdown.ts:56-63` gives a missing wiki link `href="#"`; activating it jumps to the current page's top. `web/e2e/mock.js` includes `[[Missing note]]`. | Render unresolved note as marked, non-navigable text; keep valid links intact. | TypeScript and browser interaction assertions. |
| P1 | Resource use | `src/portal/security.py:49-74` retains an expired failed-login key until that exact key is visited again; many distinct failed account names keep accumulating. | Periodically prune old keys while preserving the throttle window and lock. | Controlled-clock expiration and limit tests. |

## Examined paths without a patch claim

- `src/refhandbook/query_api.py`: the bounded output already documents SQL `LIMIT … OFFSET` and `open_node`; earlier pagination finding was invalid.
- `web/src/pages/settings.ts`, `web/frame/colors.ts`: current theme editor has palettes, per-scheme colors, accent picker, fonts and contrast logic; the older claim of only a few choices does not describe this baseline.
- `src/portal/apps.py`, `src/portal/api.py`, `deploy/templates/site.conf`: server store keys are UID scoped, JSON writes use a non-simple content type, and nginx caps body size at 4 MiB. These checks constrain the storage findings above.
- `web/src/lib/markdown.ts`: parser construction per resolver may have a cost, but no measurement or safe reuse lifetime was established; no optimization patch justified from that observation.

## Submission order

This issue list is the review checkpoint. Each confirmed ID must map to a branch, regression evidence and an explicit merge status; findings withdrawn after validation must remain marked as such. No merge or deployment is part of this review.

# PAGE N1 — Turn loop (every turn)
KIND: checklist
TAGS: research, normal
TRIGGERS: every turn; NEXT:; RECEIPT; awaiting user; new message; turn loop; one-word reply; continue
OBJECTIVE: Run one turn as a state machine: begin, process K objects card by card, end with a RECEIPT and a NEXT line.

ENTRY — signal: every turn, without exception, and certainly when the previous
reply ends with `NEXT:` or the ledger holds a K awaiting the user.

◆ The device owns the turn: `research_begin` → work the K objects with the
token → `research_end` → RECEIPT. A REFUSED is a stop: resolve what it names.

1. **BEGIN.** Call `research_begin(ledger, turn)`. Its first line holds the
   TOKEN. Every write needs the newest token and prints the next one. The
   OBLIGATIONS list is the turn's input:
   - K objects, queued or AWAITING USER;
   - PENDING hits;
   - directives;
   - stale or proposed rows;
   - stale verdicts;
   - documents behind the ledger.

   The view shows the rows changed in the last 3 turns and every live row
   the obligations name (`view="recent"`). Before building on any other row,
   read it with `research_show(ids="…")`; `view="full"` prints everything.
   Do no work before this step.
2. **REGISTER.** Record the user's message verbatim with `research_add`:
   - directives and questions as `U`, with `done-when: …` in the evidence
     when the user stated one;
   - criteria as `C`, `mandatory` or `free`;
   - premises as `A`; alternatives to one premise share a `grp`;
   - symbol definitions as `S`;
   - the readings the work depends on as `R`;
   - each file the user provides, with
     `research_doc(action="register", role="source", text=…)`.

   Origin follows §4: a minimal reading is `user`, and anything larger is
   `model`.

   **Unresolved references.** Look for these cues:
   - a possessive or definite reference ("my/our X", "that equation", "the
     lemma");
   - "last time" or "as we agreed";
   - a project name;
   - a symbol absent from `S`;
   - a named result or paper;
   - any claim about a prior decision.

   For each cue that neither this conversation nor the ledger resolves, push
   `retrieve <item>` to page RF from the `U`, **before** dispatch. Never answer
   around it, and never ask the user for what the tools can find.
3. **DISPATCH.** The K AWAITING USER is the standing continuation: leave it
   blocked. Push the object for the new `U` from the `U` itself (`frm=U#`):
   - `dispatch U#` to N3;
   - to X2 for a process question;
   - to X6 for a correction;
   - to EX for a "what if" about premises.

   A message that needs no card (an acknowledgement, a one-word answer) is
   registered and set, and pushes nothing. On the first turn of a question, or
   when the message resumes earlier work, push `enter` to N2. A card that ends
   by waiting on the user pushes page USER: that re-arms the standing K with
   the new objects instead of adding one.
4. **LOOP.** While a queued K exists and no exit below holds:
   1. Run `research_next`. The device prints the card.
   2. Run the card on the K's `on` objects. After each action write
      `⟵ basis: <ids with status> · new: <ids or none>`, citing only what §4
      permits. Read before building.
   3. Record every change with `research_add`, `research_set`,
      `research_explore`, or `research_doc`. **Replace** a cell; never append
      history into it, because the log keeps the history. A byproduct that
      changes no mandatory `C` becomes one `P` row.
   4. Pick the exit whose condition holds. Push its objects
      (`frm=K, exit=x`), then run `research_done(K, exit=x)`.

   One K runs at a time.
5. **PROPAGATE.** A write that prints PENDING needs a disposition for every hit
   (card X6) before `research_end`.
6. **SETTLE.** Every `U` is set, or carried with its reason. A document with a
   committed plan is rewritten and synced (card N4).
7. **END.** Call `research_end(ledger, turn, token)`. It refuses while any of
   the following remain:
   - a running K;
   - no continuation K;
   - a PENDING hit;
   - an unaddressed `U`;
   - an unsynced document plan;
   - a check error;
   - a turn in which no `U` was added or updated.

   Pass `idle="<why>"` only when the message truly asks nothing.
8. **SHOW.** The reply is written for the user, as prose in the user's
   language, in this order:
   - what was checked, what changed, and what it means, with the decisions
     the user is asked to make. Name a row by its id only where the user
     needs it to find the row. Each result is stated as the **current**
     state: a changed result is restated whole, never as a chain of
     "correction:" or "addendum:" fragments;
   - the RECEIPT line, verbatim;
   - the `NEXT:` line, **last**.

   The ▶/◀ processing transcript (one block per K, with its basis tags) is
   the ledger's record — the K rows and the Δ that `end` prints — and is
   not pasted into the reply. Give the transcript of a K only when the user
   asks how that step was processed.

   A reply without a RECEIPT is a skipped cycle and must say so.

**EXITS**

- **a**: every remaining K waits for the user → close with steps 5–8
- **b**: a derivation-chain step was completed (one step per turn) → the remaining K stay queued; close with steps 5–8
- **c**: `research_end` REFUSED → push `check integrity` @X7 from the last K, then return to step 4
